## A tool that required expertise to use safely

The CUI tool — used to create and manage campaigns and benefits across global markets — had grown by accretion. Feature by feature, edge case by edge case, until the original logic that held it together had disappeared. By the time I came to this project, using it correctly required significant institutional knowledge. New users made errors they didn't catch. Veterans had spreadsheets and workarounds that lived outside the system.

> The surface-level problem was UX friction. The deeper problem was that the logic of how campaigns and benefits related to each other wasn't visible in how the tool was structured.

## Build the case first, then the direction

Before any redesign conversation could start, the problem needed to be quantifiable. I developed a design business case — mapping stakeholder interviews, key user journeys, and cost impact factors into a clear executive summary. That gave the project the strategic weight to move forward.

The audit that followed wasn't about cataloguing UI issues. It was about understanding what mental model the tool was asking users to carry — then identifying where that model broke down. I mapped the objects (campaigns, benefits, rules, conditions), the relationships between them, and the failure points.

From that, I designed a vision for how the tool *should* work: one where the logic is visible, the relationships are explicit, and reusability is built in rather than hacked around.

## Six decisions that would have changed how the tool worked

The high-fidelity screens were specific enough to make design decisions real — and to give the product team something concrete to build toward.

**Intent-first campaign creation**

Instead of a blank form, users start by choosing a campaign type: Conversion, Loyalty, Referral. Three intents that map to how marketing teams actually think — not how the database categorises them. The form still exists; intent comes first.

<FullImage src="/Work/CUI/Create%20Campaign.jpg" alt="Create Campaign — template selection screen" caption="Entry points based on campaign intent, not system structure." contained />

**A visible creation process**

The sidebar shows every step: Create details → Set Schedule → Define rules → QA → Generate voucher codes → Validate → Launch. Users always know where they are and what's next. The QA gate is built into the flow, not handled in a spreadsheet afterward.

**Readable rule logic**

The original tool had rules; they were just invisible. The redesign makes discount logic explicit: conditions, effects, tiers — all composable and readable before anything is applied. If redemption count equals 1, apply 50%. If 2, apply 40%. You can see what the system will do.

<FullImage src="/Work/CUI/Create%20benefit%20definition.jpg" alt="Benefit definition — rule builder with conditions and effects" caption="Conditions and effects as explicit, composable rules — each discount tier visible and editable before anything is applied." contained />

**Benefit definitions as reusable objects**

A benefit definition is no longer a one-off configuration — it's a named object that can be referenced across campaigns. The detail page shows where it's being used, which markets, and how each is performing.

<FullImage src="/Work/CUI/Benefit%20definition%20details%20page.jpg" alt="Benefit definition detail page" caption="Reusability made visible — campaigns using this definition, effects applied, performance by market." contained />

**SKU-level discount visibility**

The audit found users validating SKU-level pricing in external spreadsheets because the tool didn't surface it. A dedicated view shows the pricing grid at the level that matters for voucher generation, exportable as CSV.

<FullImage src="/Work/CUI/SKU%20based%20Benefit%20Definition.jpg" alt="SKU based Benefit Definition — pricing grid" caption="Discount logic visible at SKU and box size level — what was previously validated in spreadsheets." contained />

**Errors with resolution paths**

The old tool had error states; it didn't have resolution. The new activity panel categorises warnings from errors, timestamps them by market, and links directly to the affected campaign. Not just an alert — a path to the fix.

<FullImage src="/Work/CUI/CA-01.jpg" alt="Activity — Errors and Warnings panel" caption="Categorised, timestamped, linked to the affected campaign — the system tells you what to do next." contained />

## The creation process, made explicit

One of the quieter problems was that users didn't know what creating a campaign actually involved. Experienced users had the steps memorised. New users didn't — and the tool didn't tell them.

## What vision work is actually for

This project didn't ship a redesign. The output was a design business case and a high-fidelity vision — a clear picture of where the product should go, before anyone starts making incremental changes. Without that, every incremental change just adds to the confusion.
